# 📝 СОЗДАНИЕ ТЕСТОВОЙ ЗАЯВКИ ДЛЯ ДЕМОНСТРАЦИИ

## ❌ ПРОБЛЕМА:

Запрос `GET /api/requests` возвращает пустой массив `[]`.

**Причина:** В БД нет заявок для текущего пользователя или они не попадают под фильтр по датам.

---

## ✅ РЕШЕНИЕ: Создать тестовую заявку

### Вариант 1: Через API (РЕКОМЕНДУЕТСЯ)

#### Шаг 1: Получите список услуг

1. В Swagger выполните `GET /api/services` (с авторизацией)
2. Запомните ID одной из услуг (например, `1`)

#### Шаг 2: Создайте черновик заявки

1. В Swagger выполните `GET /api/requests/draft` (с авторизацией)
2. Это создаст черновик заявки, если его еще нет

#### Шаг 3: Добавьте услугу в заявку

1. В Swagger выполните `POST /api/requests/add-service` (с авторизацией):

```json
{
  "service_id": 1
}
```

#### Шаг 4: Отправьте заявку

1. В Swagger выполните `PUT /api/requests/{id}/submit` (с авторизацией)
   - Замените `{id}` на ID заявки из шага 2

#### Шаг 5: Проверьте список заявок

1. В Swagger выполните `GET /api/requests` (с авторизацией)
2. Должна вернуться заявка

---

### Вариант 2: Через Adminer (SQL)

1. Откройте Adminer: http://localhost:8080
2. Войдите: user / password / deposits
3. Выполните SQL:

```sql
-- Проверьте пользователя
SELECT id, email, role FROM users WHERE email = 'user@example.com';

-- Создайте заявку (замените user_id на реальный ID пользователя)
INSERT INTO requests (user_id, status, created_at, updated_at) 
VALUES (
  (SELECT id FROM users WHERE email = 'user@example.com'),
  'formed',
  '2026-01-15 10:00:00',
  '2026-01-15 10:00:00'
)
RETURNING id;

-- Добавьте услугу в заявку (замените request_id и service_id)
INSERT INTO request_services (request_id, service_id, quantity)
VALUES (
  (SELECT id FROM requests WHERE user_id = (SELECT id FROM users WHERE email = 'user@example.com') ORDER BY id DESC LIMIT 1),
  1,
  1
);

-- Проверьте результат
SELECT r.id, r.user_id, r.status, r.created_at, u.email 
FROM requests r 
JOIN users u ON r.user_id = u.id 
WHERE u.email = 'user@example.com';
```

---

### Вариант 3: Быстрое создание через API (один запрос)

Если у вас уже есть черновик:

1. Добавьте услугу: `POST /api/requests/add-service` с `{"service_id": 1}`
2. Отправьте заявку: `PUT /api/requests/{id}/submit`

---

## 🔍 ПРОВЕРКА:

После создания заявки:

1. Выполните `GET /api/requests` (без фильтров):
   ```
   GET http://localhost:3001/api/requests
   ```
   Должна вернуться заявка

2. Выполните с фильтром по датам:
   ```
   GET http://localhost:3001/api/requests?date_from=2026-01-01&date_to=2026-01-31
   ```
   Должна вернуться заявка, если она создана в январе 2026

---

## ⚠️ ВАЖНО О ФИЛЬТРАХ:

Фильтр работает по полю `created_at` (дата создания заявки), а не по датам услуг!

- Если заявка создана **сегодня** (7 декабря 2025), а фильтр `date_from=2026-01-01`, то заявка **не попадет** в результат
- Используйте правильные даты для фильтра:
  - Для заявки, созданной сегодня: `date_from=2025-12-07&date_to=2025-12-07`
  - Или создайте заявку с датой в будущем через SQL

---

## 🚀 БЫСТРОЕ РЕШЕНИЕ:

**Создайте заявку через SQL с датой в январе 2026:**

```sql
-- В Adminer выполните:
INSERT INTO requests (user_id, status, created_at, updated_at) 
VALUES (
  (SELECT id FROM users WHERE email = 'user@example.com'),
  'formed',
  '2026-01-15 10:00:00',
  '2026-01-15 10:00:00'
);

-- Добавьте услугу
INSERT INTO request_services (request_id, service_id, quantity)
VALUES (
  (SELECT id FROM requests WHERE user_id = (SELECT id FROM users WHERE email = 'user@example.com') ORDER BY id DESC LIMIT 1),
  1,
  1
);
```

После этого запрос `GET /api/requests?date_from=2026-01-01&date_to=2026-01-31` должен вернуть заявку!
