# 📋 НАЗНАЧЕНИЕ СТРАНИЦЫ "РАСЧЕТЫ" (RequestsPage)

## 🎯 ЗАЧЕМ НУЖНА ЭТА СТРАНИЦА?

Страница "Расчеты" (`/requests`) - это **история всех отправленных расчетов вкладов**.

### Аналогия:
Представьте интернет-магазин:
- **Корзина** (`/draft`) = товары, которые вы собираетесь купить (черновик)
- **Расчеты** (`/requests`) = история всех ваших заказов (что уже отправлено)

---

## 📊 ЧТО ПОКАЗЫВАЕТ СТРАНИЦА:

### Для обычного пользователя (user):
- ✅ **Только свои расчеты** - видит только те расчеты, которые он сам отправил
- ✅ **История расчетов** - все расчеты, которые были отправлены (статус: `formed`, `submitted`, `completed`)
- ✅ **Статусы расчетов:**
  - `draft` - черновик (не показывается, он в корзине)
  - `formed` - сформирован (отправлен пользователем)
  - `submitted` - отправлен на обработку
  - `completed` - завершен модератором
  - `deleted` - удален (не показывается)

### Для модератора (moderator):
- ✅ **Все расчеты всех пользователей** - видит все расчеты в системе
- ✅ **Управление расчетами:**
  - Кнопка "Завершить" - меняет статус на `completed`
  - Кнопка "Удалить" - логически удаляет расчет (статус `deleted`)

---

## 🔄 ЖИЗНЕННЫЙ ЦИКЛ РАСЧЕТА:

1. **Создание черновика** (`/draft`)
   - Пользователь добавляет месяцы в корзину
   - Статус: `draft`
   - Видно только в корзине

2. **Отправка расчета** (кнопка "Отправить расчет")
   - Пользователь нажимает "Отправить расчет" в корзине
   - Статус меняется на `formed`
   - Расчет появляется в списке "Расчеты"

3. **Обработка модератором** (`/requests`)
   - Модератор видит расчет со статусом `formed`
   - Может нажать "Завершить"
   - Статус меняется на `completed`

4. **Удаление** (опционально)
   - Модератор может удалить расчет
   - Статус меняется на `deleted`
   - Расчет скрывается из списка

---

## 💡 ПРАКТИЧЕСКОЕ ПРИМЕНЕНИЕ:

### Пример использования:

**Сценарий 1: Пользователь хочет посмотреть историю своих расчетов**
1. Пользователь заходит на `/requests`
2. Видит список всех своих отправленных расчетов
3. Может посмотреть, какие расчеты уже завершены, какие еще обрабатываются

**Сценарий 2: Модератор обрабатывает расчеты**
1. Модератор заходит на `/requests`
2. Видит все расчеты всех пользователей
3. Для каждого расчета может:
   - Завершить расчет (кнопка "Завершить")
   - Удалить расчет (кнопка "Удалить")

## 🔍 ОТЛИЧИЕ ОТ КОРЗИНЫ:

| Корзина (`/draft`) | Расчеты (`/requests`) |
|---------------------|----------------------|
| Текущий черновик | История всех расчетов |
| Только один расчет | Много расчетов |
| Можно редактировать | Только просмотр |
| Статус: `draft` | Статусы: `formed`, `submitted`, `completed` |
| Для пользователя | Для пользователя и модератора |

---

## ✅ ВЫВОД:

Страница "Расчеты" нужна для:
1. **Истории** - посмотреть все отправленные расчеты
2. **Управления** - модератор может завершать и удалять расчеты
3. **Отслеживания статусов** - видеть, какие расчеты обработаны, какие нет
4. **Разделения ролей** - пользователь видит только свои, модератор - все

**Это стандартная функциональность для любого приложения с заявками/заказами!**
