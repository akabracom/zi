## 1. ОСТАНОВКА 3-Й ЛАБЫ (BACKEND)

### ⚠️ ВАЖНО: Полная остановка всех контейнеров 3-й лабы

**Выполните в PowerShell или CMD:**

```powershell
# 1. Перейдите в папку 3-й лабы
cd C:\spa-frontend\backend

# 2. Остановите и удалите все контейнеры
docker-compose down

# 3. Проверьте, что контейнеры остановлены
docker ps -a | Select-String "deposits-db|minio|deposits-app|adminer"

# 4. Если контейнеры все еще есть, принудительно удалите их
docker rm -f deposits-db minio deposits-app adminer 2>$null

# 5. Очистите неиспользуемые сети (если нужно)
docker network prune -f

# 6. Проверьте, что порты свободны
netstat -ano | findstr ":3001 :5432 :8080 :9000 :9001"
```

**Или используйте готовый скрипт:**

```cmd
cd C:\spa-frontend\backend
docker-compose down
docker rm -f deposits-db minio deposits-app adminer 2>nul
docker network prune -f
```

### ✅ Проверка остановки:

После выполнения команд проверьте:

```powershell
# Должно быть пусто (контейнеры остановлены)
docker ps

# Или только контейнеры других проектов
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
```

**Ожидаемый результат:** Контейнеры `deposits-db`, `minio`, `deposits-app`, `adminer` из папки `backend` должны быть остановлены и удалены.

## 2. ЗАПУСК 4-Й ЛАБЫ (SPA_Dep)

```powershell
cd C:\spa-frontend\SPA_Dep
```


## 4. ЧЕКЛИСТ СКРИНШОТОВ

### 📸 ПОРЯДОК ДЕМОНСТРАЦИИ (строго по порядку):

---

### **СКРИНШОТ 1: Аутентификация через Swagger (режим инкогнито)**

**Что сделать:**

1. Откройте браузер в режиме инкогнито (Ctrl+Shift+N)
2. Перейдите: http://localhost:3001/swagger/index.html
3. Найдите endpoint `POST /auth/login` или `POST /auth/register`
4. Выполните аутентификацию:
   - **Для регистрации:**
     ```json
     {
       "email": "user@example.com",
       "password": "password123",
       "name": "Test User"
     }
     ```
   - **Для входа:**
     ```json
     {
       "email": "user@example.com",
       "password": "password123"
     }
     ```
5. Получите ответ с JWT токеном

**Что показать на скриншоте:**
- ✅ Swagger UI в режиме инкогнито
- ✅ Запрос `POST /auth/login` или `/auth/register`
- ✅ Request body с данными
- ✅ Response с JWT токеном (поле `token`)
- ✅ Данные пользователя (email, role, user_id)

**Важно:** Сохраните JWT токен из ответа для следующих шагов!

---

### **СКРИНШОТ 2: Получение списка заявок через Swagger**

**Что сделать:**

1. В том же Swagger (режим инкогнито)
2. Найдите endpoint `GET /requests`
3. Нажмите "Authorize" (замочек) вверху Swagger
4. Вставьте JWT токен из предыдущего шага (формат: `Bearer <token>`)
5. Выполните запрос `GET /requests`

**Что показать на скриншоте:**
- ✅ Swagger UI с авторизацией (замочек зеленый)
- ✅ Запрос `GET /requests`
- ✅ Response со списком заявок (массив заявок или пустой массив)
- ✅ Статус 200 OK

---

### **СКРИНШОТ 3: Получение Cookie из браузера**

**Что сделать:**

1. В том же браузере (режим инкогнито) откройте DevTools (F12)
2. Перейдите на вкладку **Application** (Chrome) или **Storage** (Firefox)
3. В левой панели найдите **Cookies** → `http://localhost:3001`
4. Найдите cookie с сессией (обычно `session` или `token`)

**Что показать на скриншоте:**
- ✅ DevTools открыт
- ✅ Вкладка Application/Storage
- ✅ Список Cookies для `localhost:3001`
- ✅ Значение cookie (можно замазать часть для безопасности)

**Альтернатива:** Если cookie нет, используйте JWT токен из ответа аутентификации.

---

### **СКРИНШОТ 4: GET списка заявок БЕЗ авторизации (401/403 для гостя)**

**Что сделать:**

1. Откройте **Insomnia** или **Postman**
2. Создайте новый запрос: `GET http://localhost:3001/api/requests`
3. **НЕ добавляйте** заголовок `Authorization` или `Cookie`
4. Выполните запрос

**Что показать на скриншоте:**
- ✅ Insomnia/Postman с запросом `GET /api/requests`
- ✅ Headers (пустые, без Authorization)
- ✅ Response с кодом **401 Unauthorized** или **403 Forbidden**
- ✅ Сообщение об ошибке (например: "authorization header required")

---

### **СКРИНШОТ 5: GET списка заявок С авторизацией (для создателя - только его заявки)**

**Что сделать:**

1. В **Insomnia/Postman** создайте запрос: `GET http://localhost:3001/api/requests`
2. Добавьте заголовок:
   - **Вариант 1 (JWT):** 
     - Header: `Authorization`
     - Value: `Bearer <ваш_jwt_токен>` (из Swagger)
   - **Вариант 2 (Cookie):**
     - Header: `Cookie`
     - Value: `<имя_cookie>=<значение>` (из браузера)
3. Выполните запрос

**Что показать на скриншоте:**
- ✅ Insomnia/Postman с запросом `GET /api/requests`
- ✅ Headers с `Authorization: Bearer <token>` или `Cookie: <value>`
- ✅ Response со статусом **200 OK**
- ✅ Список заявок (только заявки текущего пользователя)
- ✅ В ответе видно, что заявки принадлежат пользователю с email из токена

**Важно:** Убедитесь, что в ответе только заявки создателя (проверьте `user_id` в заявках).

---

### **СКРИНШОТ 6: PUT завершения заявки - для создателя (403 Forbidden)**

**Что сделать:**

1. В **Insomnia/Postman** создайте запрос: `PUT http://localhost:3001/api/requests/{id}/complete`
   - Замените `{id}` на ID существующей заявки (из предыдущего запроса)
2. Добавьте заголовок `Authorization: Bearer <токен_создателя>`
3. Выполните запрос

**Что показать на скриншоте:**
- ✅ Insomnia/Postman с запросом `PUT /api/requests/{id}/complete`
- ✅ Headers с `Authorization: Bearer <токен_создателя>`
- ✅ Response с кодом **403 Forbidden**
- ✅ Сообщение об ошибке (например: "insufficient permissions" или "only moderator can complete")

---

### **СКРИНШОТ 7: PUT завершения заявки - для модератора (успех и обновление полей)**

**Что сделать:**

1. **Создайте пользователя с ролью "moderator":**
   - Через Swagger: `POST /auth/register` с данными:
     ```json
     {
       "email": "moderator@example.com",
       "password": "password123",
       "name": "Moderator",
       "role": "moderator"
     }
     ```
   - Или через Adminer: добавьте пользователя в БД с `role = 'moderator'`
2. **Войдите как модератор:**
   - `POST /auth/login` с `moderator@example.com`
   - Получите JWT токен модератора
3. В **Insomnia/Postman** создайте запрос: `PUT http://localhost:3001/api/requests/{id}/complete`
4. Добавьте заголовок `Authorization: Bearer <токен_модератора>`
5. Выполните запрос

**Что показать на скриншоте:**
- ✅ Insomnia/Postman с запросом `PUT /api/requests/{id}/complete`
- ✅ Headers с `Authorization: Bearer <токен_модератора>`
- ✅ Response с кодом **200 OK** или **204 No Content**
- ✅ Сообщение об успехе (например: `{"status": "completed"}`)
- ✅ **Дополнительно:** Показать обновленную заявку через `GET /api/requests/{id}` - поля должны быть обновлены (например, `status = 'completed'`, `updated_at` изменен)

### **СКРИНШОТ 9: Содержимое Redis через CMD (сессии)**

**Что сделать:**

1. Откройте **CMD** или **PowerShell**
2. Подключитесь к Redis:
   ```cmd
   docker exec -it redis redis-cli
   ```
3. Выполните команды:
   ```redis
   KEYS *
   GET token:user@example.com
   HGETALL session:user:1
   ```
   (Замените `user@example.com` и `1` на реальные значения)

**Что показать на скриншоте:**
- ✅ CMD/PowerShell с подключением к Redis
- ✅ Команда `KEYS *` - список всех ключей
- ✅ Команда `GET token:...` - JWT токен пользователя
- ✅ Команда `HGETALL session:user:...` - данные сессии (email, role, login_at)
- ✅ Видно структуру данных в Redis

**Важно:** Покажите, что в Redis хранятся:
- Токены: `token:<email>` → `<jwt_token>`
- Сессии: `session:user:<id>` → `{email, role, login_at}`
