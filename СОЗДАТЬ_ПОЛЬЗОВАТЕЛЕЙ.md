## ✅ РЕШЕНИЕ 1: Создать пользователя через Swagger (РЕКОМЕНДУЕТСЯ)

### Шаг 1: Регистрация через Swagger

1. Откройте Swagger: http://localhost:3001/swagger/index.html
2. Найдите endpoint `POST /auth/register`
3. Выполните запрос с данными:

```json
{
  "email": "user@example.com",
  "password": "password123",
  "name": "Test User"
}
```

4. Получите JWT токен из ответа

### Шаг 2: Вход через Swagger

1. Найдите endpoint `POST /auth/login`
2. Выполните запрос с теми же данными:

```json
{
  "email": "user@example.com",
  "password": "password123"
}
```

3. Получите JWT токен

## ✅ РЕШЕНИЕ 2: Создать пользователя через Adminer (SQL)

### Шаг 1: Откройте Adminer

1. Перейдите: http://localhost:8080
2. Войдите:
   - **Система:** PostgreSQL
   - **Сервер:** deposits-db
   - **Пользователь:** user
   - **Пароль:** password
   - **База данных:** deposits

### Шаг 2: Выполните SQL

```sql
-- Проверьте, есть ли пользователи
SELECT id, email, name, role FROM users;

-- Если пользователей нет, создайте их
-- Пароль для всех: "password123"
-- Хеш сгенерирован с помощью bcrypt (cost=10)
INSERT INTO users (email, name, password, role) VALUES
  ('user@example.com', 'Test User', '$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy', 'user'),
  ('moderator@example.com', 'Test Moderator', '$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy', 'moderator')
ON CONFLICT (email) DO NOTHING;

-- Проверьте результат
SELECT id, email, name, role FROM users;
```

### Шаг 3: Войдите через Swagger

Теперь попробуйте войти с:
- Email: `user@example.com`
- Password: `password123`

## ✅ РЕШЕНИЕ 3: Пересоздать БД с миграциями

Если пользователи должны были создаться автоматически, но не создались:

```cmd
cd C:\spa-frontend\SPA_Dep

# Остановите контейнеры
docker-compose down

# Удалите volume с данными БД
docker volume rm spa_dep_pg_data

# Запустите заново (миграции применятся автоматически)
docker-compose up -d

# Подождите 15 секунд
timeout /t 15 /nobreak
```

После этого пользователи должны быть созданы автоматически из миграции `01_users.sql`.
